# Carbon-aware cloud architecture for an online education platform

Course project (Introduction to Cloud Computing, Topic 5: cloud architecture design).
Compares **Design A** (2 always-on EC2 instances + ALB) with **Design B** (AWS Lambda arm64 +
carbon-aware batch scheduler) on cost, estimated energy and estimated CO2e.

## IMPORTANT: what is measured and what is modelled
* **Measured:** CPU time of each endpoint (`sim/measure_workload.py` -> `results/measured_workload.json`).
* **Published:** AWS list prices and Cloud Carbon Footprint power coefficients (see Table 3 of the report).
* **Assumed / synthetic:** I/O wait, cold-start time, batch-job sizes, grid-intensity *profiles* and regional
  levels (`src/grid.py`). The experiments are a **simulation**; nothing was run on a live AWS account.

## Layout
    src/         core.py (app logic) | lambda_api.py (Design B) | vm_app.py (Design A)
                 carbon_model.py | grid.py | scheduler.py | scheduler_lambda.py (AWS stub)
    sim/         measure_workload.py | run_experiments.py | make_figures.py
    loadtest/    locustfile.py       (run against both designs on AWS)
    infra/       template.yaml       (AWS SAM template for Design B)
    tests/       10 unit tests       results/ figures/
    report/      build scripts for the Word report (python-docx-free XML builder, uses the course template)

## Reproduce
    pip install -r requirements.txt
    python3 -m pytest -q tests          # 10 tests
    python3 sim/run_experiments.py      # eight experiments -> results/*.csv|json   (~1 min)
    python3 sim/make_figures.py         # writes figures/*.png
(Re-running `measure_workload.py` re-measures CPU times on your machine, which slightly changes all numbers.)

## Turn the simulation into a real measurement (recommended next step)
1. `sam build && sam deploy` (infra/template.yaml) for Design B; launch 2 x t3.medium + ALB running
   `gunicorn vm_app:application` for Design A.
2. Run `locust -f loadtest/locustfile.py --host <endpoint>` against each design with identical users.
3. Replace modelled durations by CloudWatch `REPORT` lines (Duration, Billed Duration, Max Memory Used) and
   utilisation by CloudWatch CPUUtilization; compare with the AWS Sustainability service data.
4. Replace `grid.py` by real hourly intensity data (e.g. Electricity Maps) and re-run Experiments 3-4.
Set a billing alarm before deploying anything.

## Experiments
1 memory/architecture sweep | 2 Design A vs B | 3 regions | 4 carbon-aware scheduling | 5 break-even |
6 one-at-a-time sensitivity | 7 stronger VM baselines (Arm, reserved) | 8 exam-start flash crowd.
